## 一、已确认区域

### 1. 项目定位与展示原则

- 当前项目定位为前端看板项目。
- 页面展示模块以 `项目框架.txt` 中写明的模块为准，不允许因为开发复用而删除、合并或重排甲方原始展示模块。
- 销售指标、客户指标、趋势指标、健康度总览、待跟进提醒、客户列表、客户详情等模块均属于甲方明确要看的页面展示内容。
- 开发侧可以复用时间规则、数据清洗逻辑、指标计算函数、图表组件、表格组件，但复用只发生在实现层，不能改变产品展示结构。
- 客户状态、同比 / 环比及其他尚无准确数据或业务逻辑支撑的指标继续暂停。
- 销售金额的平台字段筛选、订单过滤、销售金额计算和销售日期标准化规则，已由甲方授权的 `data/平台数据处理.txt` 补充。
- 客户活跃度新业务标准已确认并落地；旧版五维健康度不再作为当前业务标准推进。跟进提醒类型已由甲方授权的 `客户健康度与跟进提醒规则.md` 补充，当前进入具体触发阈值澄清阶段。

### 2. 组织层级与聚合维度

已确认看板展示层级为：

```text
主管
├── 组长 / 小组
│   ├── 平台
│   ├── 平台
│   └── 平台
```

- 主管视角：查看各组长 / 各小组信息，以及各小组合计信息。
- 组长视角：查看自己小组下各平台信息，以及本组合计信息。
- “组长”是主管下的管理对象。
- “小组”是组长负责的数据范围。
- “平台”是组长 / 小组下的二级统计维度。
- 主管端聚合维度：组长 / 小组。
- 组长端聚合维度：平台。
- 第一版按「组长管理自己小组」处理，不设计一人多组权限。

### 3. 主管端页面结构

主管端初始页面已确认包括 4 个：

```text
主管端
├── 渠道总览页
├── 私域组展示页
├── 达人组展示页
└── 分销组展示页
```

其中三个组展示页都是页面集合 / 容器，内部包含：

```text
组展示页
├── 组别分析页
├── 客户列表页
└── 客户详情页
```

已确认规则：

- 主管可以访问渠道总览页。
- 主管可以访问私域组、达人组、分销组三个组展示页。
- 主管可以查看各组数据，包括组别分析页、客户列表页、客户详情页数据。
- 主管只负责查看各组数据，不负责管理小组。
- 主管端不单独做组排名页；如需对比，通过表格排序或图表维度切换满足。

### 4. 组长端页面结构

组长端页面已确认：

```text
组长端
└── 自己所属组的展示页
    ├── 组别分析页
    ├── 客户列表页
    ├── 客户详情页
    └── 数据上传页
        ├── 销售数据上传页
        └── 客户名单上传页
```

已确认规则：

- 组长只能看到自己所属组的展示页集合。
- 组长不能访问其他组页面。
- 组长不能查看其他组数据。
- 组长管理自己的小组。
- 组长端直接显示数据上传页。
- 数据上传页和组别分析页、客户列表页、客户详情页同级。
- 数据上传页内部包含销售数据上传页和客户名单上传页。
- 主管端不显示上传入口；主管对销售数据和客户名单具有查看权限但不能上传。

### 5. 页面权限与字段权限

已确认规则：

- 主管端和组长端看到的页面集合不同。
- 系统根据登录账号绑定的角色和所属组进入对应页面。
- 主管可以查看全部小组数据。
- 组长只能查看自己小组数据。
- 主管和组长在各自有权限的数据范围内，全部字段可见。
- 第一版不做字段级权限差异。
- 业务负责人维度暂定保留，但作为可选维度处理，不能强绑定核心页面、筛选、表格、排序或图表逻辑。

### 6. 第一版登录账号方案

已确认采用普通网页登录 / 系统账号分发。

账号规则：

- 第一版只设置 4 个账号：
  - 1 个主管账号。
  - 3 个组长账号。
- 三个组长账号分别绑定私域组、达人组、分销组。
- 账号全部由系统侧统一设置和分发。
- 不由主管或组长创建账号。
- 账号密码在系统首次初始化时生成一次。
- 账号密码后续保持不变，不在每次启动时重新生成。

登录模块只负责三件事：

1. 首次初始化生成 4 组账号密码。
2. 登录时校验账号密码是否正确。
3. 校验通过后按账号权限跳转。

默认跳转规则：

- 主管账号登录后默认进入渠道总览页。
- 组长账号登录后默认进入自己小组的组别分析页。

第一版明确不做：

- 密码修改。
- 密码找回。
- 密码重置。
- 账号停用。
- 账号管理页面。
- 账号密码文件保管与发放流程。
- 手动修改 URL 等额外越权场景提示或跳转。

### 7. 全局时间规则

已确认规则：

- 所有页面和账号统一使用北京时间。
- 页面数据每日更新。
- 每日数据更新时间暂定为北京时间 12:00，后续可能调整。
- 如果同步尚未完成，页面先展示昨日数据。
- 同步完成后立即更新页面。
- 看板页面只展示当前筛选日期，不展示数据更新时间。
- 默认展示北京时间前一天数据。
- 不展示当日数据。
- 数据起始日期从 2025-02-01 开始。

日期选择规则：

- 自定义开始日期不能早于 2025-02-01。
- 自定义结束日期最多只能选择到昨日。
- 近7日和近30日按自然日计算。
- 近7日和近30日包含周末。

无数据展示规则：

- 金额类指标无数据展示 0。
- 数量类指标无数据展示 0。
- 无法计算的比率展示空或“暂无”。
- 规则未确认模块展示“规则待确认”。
- 列表无数据展示“暂无数据”。
- 上传记录为空展示“暂无上传记录”。

### 9. 销售金额展示周期与平台清洗规则

销售金额页面展示周期已确认：

```text
销售金额
├── 昨日销售金额
├── 近7日销售金额
├── 近30日销售金额
└── 自定义时间销售金额
```

已确认：

- 这四类是展示周期拆分，不是四套不同指标。
- 底层采用统一标准化结果字段，再按时间范围聚合。
- 各平台销售金额不能写在页面组件中，必须放在数据清洗 / 指标计算层。
- 上传文件格式支持 CSV 或 XLSX。
- 字段名来自甲方从平台文件中提取的结果，默认不会出现字段名不一致。
- 日期格式由系统统一转换，标准化后的 `sales_date` 必须为 `yyyy-mm-dd`。
- 金额字段不会出现货币符号，按纯数值字段解析。

统一处理流程已确认：

```text
原始 CSV / XLSX 文件
→ 按平台筛选“有用字段”
→ 按平台销售计算规则过滤订单
→ 按平台公式计算销售金额 / 商品数量
→ 将销售日期统一格式化为 yyyy-mm-dd
→ 输出统一销售事实数据
```

第一版标准化字段建议至少包含：

```text
platform
sales_date
sales_amount
product_code
product_quantity
customer_name / customer_key
group_type
source_fields
```

各平台销售数据处理规则已确认：

| 平台 | 有用字段 | 销售日期字段 | 过滤条件 | 销售金额计算 | 商品数量计算 / 备注 |
| --- | --- | --- | --- | --- | --- |
| 抖音平台 | 商品编码、订单应付金额、支付完成时间、达人ID、售后状态、商品数量、流量来源、订单状态 | 支付完成时间 | 订单状态 = 已完成；售后状态 ≠ 退款成功 | 订单应付金额 | 商品数量；流量来源为小店自卖时达人ID为 0 |
| 快手小店 | 订单支付时间、订单状态、实付款、成交数量、售后状态、渠道、CPS达人ID、团长ID | 订单支付时间 | 订单状态 = 交易成功；售后状态 ≠ 退款成功 | 实付款 | 成交数量；客户指标统计时注意渠道选择分销 |
| 微店 | 订单状态、订单实际收款金额、商品数量、支付时间、SKU编码、商品售后、带货ID | 支付时间 | 订单状态 = 已完成；商品售后 = 无 | 订单实际收款金额 | 商品数量 |
| 有赞平台 | 订单状态、订单类型、商品数量、订单实付金额、买家昵称、商品退款状态、规格编码、订单创建日期 | 订单创建日期 | 订单状态 = 已完成；商品退款状态为空 | 订单实付金额 | 商品数量 |
| 快团团平台 | 数量、商品编码、跟团号、商品金额、订单状态、支付时间、支付状态 | 支付时间 | 订单状态 ≠ 已取消；支付状态 = 已支付 | 数量 × 商品金额 | 数量；订单取消时商品数量会自动变为 0，支付状态为已关闭表示发生退款 |
| 聚水潭线上平台 | 付款日期、商品编码、订单状态、分销商、店铺、实发数量、实发金额、实退数量、实退金额 | 付款日期 | 订单状态 = 已发货 | 实发金额 - 实退金额 | 实发数量 - 实退数量；客户实体：分销商有值则客户取分销商，否则取店铺 |

### 11. 健康度模块展示与评分框架

健康度模块展示周期已确认：

```text
昨日
近7日
近30日
自定义时间
```

每个周期展示 4 个指标：

```text
健康客户数
观察客户数
风险客户数
流失预警客户数
```

展示维度已确认：

- 主管端渠道总览页展示整体和各组。
- 组展示页 / 组别分析页展示当前组整体和各平台。

客户活跃度评分规则已确认一部分：

| 范围 | 状态 |
| --- | --- |
| 私域组：有赞、快团团 | 已确认并可计算 |
| 分销组：聚水潭平台、阿里巴巴平台 | 已确认并可计算 |
| 达人组：抖店、快手小店、微店 | 已确认并可计算，固定按业务半年口径 |

私域组 / 分销组当前使用 100 分制客户活跃度规则：

```text
日维度：customer_score = 0.4 * last_order_score + 0.3 * week_score + 0.3 * month_score
周维度：customer_score = week_score
月维度：customer_score = month_score
自定义时间段：customer_score = 0.5 * week_score + 0.5 * month_score
```

达人组当前使用业务半年客户活跃度规则：

```text
业务半年：2-7月、8-次年1月
count = 六个月月拿货次数之和
money = 六个月月拿货金额之和
customer_score = 0.4 * count_score + 0.6 * money_score
```

达人组不论前端传入什么时间维度，都只根据传入日期判断所属业务半年，并按该半年范围汇总客户活跃程度。

客户活跃状态已确认：高活跃、活跃、稳定、观察、风险、流失预警、流失。

旧版五维健康度已关闭：

```text
销售金额表现
拿货频次表现
最近一次拿货时间
产品结构健康度
同比 / 环比趋势
```

上述五维评分框架不再作为当前业务标准推进，不再继续确认逐项得分、扣分原因、健康等级或硬条件优先级。

当前客户状态判断以客户活跃度新业务标准为准：

- 私域组 / 分销组客户活跃度评分规则已确认，可以返回 `customer_score` 和 7 档 `state`。
- 达人组客户活跃度评分规则已确认，按业务半年返回 `customer_score` 和 7 档 `state`。
- `/api/customers/health-score` 继续作为单客户评分入口，但返回当前客户活跃度评分。
- `/api/customers/activity-summary` 返回客户活跃程度状态汇总。

待跟进提醒模块展示周期已确认：

```text

```

每个周期展示 3 个指标：

```text

```

展示维度已确认：

- 组展示页 / 组别分析页展示当前组整体和各平台。

跟进提醒类型草案已补充：

| 提醒类型 | 触发条件框架 | 建议动作 |
| --- | --- | --- |
| 近 7 天未拿货 | 重点客户近 7 天无有效订单 | 联系客户确认近期销售和补货计划 |
| 近 30 天未拿货 | 客户近 30 天无有效订单 | 判断是否流失，了解停货原因 |
| 销售环比下降 | 当前周期销售金额较上期下降超过阈值 | 确认客户库存、活动、价格和竞品影响 |
| 销售同比下降 | 当前周期较去年同期下降超过阈值 | 复盘全年合作变化，制定恢复计划 |
| 主推产品下降 | 核心产品拿货金额或数量明显下降 | 确认产品动销、价格、库存和素材问题 |
| 产品结构变窄 | 拿货产品数量减少并集中在少数产品 | 推荐组合产品或新品，提升产品结构稳定性 |
| 健康度变差 | 从健康变为观察、风险或流失预警 | 业务优先跟进；第一版页面只展示建议，不提供在线填写反馈功能 |

跟进提醒输出字段草案已补充：

```text
客户 ID（数据字段到位后确认）
客户名称
所属组别
负责业务（可选维度）
提醒类型
提醒原因
```

### 16. 数据上传页与上传权限

已确认第一版后台会先处理历史销售数据和历史客户名单数据，前端上传入口负责最新数据上传。

上传权限：

- 组长只能看到自己小组的数据上传入口。
- 主管具有销售数据和客户名单查看权限，但不能上传。
- 主管端不显示上传入口。

上传入口：

- 组长展示页新增“数据上传页”。
- 数据上传页与组别分析页、客户列表页、客户详情页同级。
- 数据上传页包含两个子页面：
  - 销售数据上传页。
  - 客户名单上传页。

上传粒度：

- 销售数据按平台分别上传。
- 客户名单按平台分别上传。
- 销售数据上传页展示当前组内各平台子页，并在平台子页内提供上传入口。
- 客户名单上传页展示当前组内各平台子页，并在平台子页内提供上传入口。
- 一个文件只对应一个平台。
- 各平台可以分开做单独上传工作流。

上传格式与字段规则：

- 上传文件格式支持 CSV 或 XLSX。
- 销售数据上传字段模板按 `data/平台数据处理.txt` 中各平台“有用字段”处理。
- 客户名单字段仍需要以后续客户名单文件为准。
- 字段名来自平台文件提取，默认不会出现字段名不一致。
- 系统仍保留必要上传校验。

历史数据与前端上传边界：

- 后台一开始会处理历史销售数据。
- 后台一开始会处理历史客户名单数据。
- 前端销售数据上传入口只负责最新销售数据。
- 前端客户名单上传入口只负责最新客户名单数据。

覆盖规则：

- 当日反复上传时，通过上传文件名计算哈希。
- 哈希值相同，则对当日上传数据执行覆盖。
- 销售数据和客户名单均采用该覆盖规则。

上传频率和提示：

- 前端上传入口负责最新数据上传。
- 每日数据更新时间暂定北京时间 12:00，后续可能调整。
- 看板页面只展示当前筛选日期，不展示数据更新时间。
- 销售数据上传页需要提示数据库已更新到某年某月某日的数据。

上传失败提示：

- 上传失败或字段不匹配时，需要展示错误行号。
- 需要展示错误字段。
- 方便组长修改后重传。

### 16. 当前开发范围建议

当前页面、权限、账号、上传入口、上传记录、客户列表交互、空状态、销售金额平台清洗规则、健康度框架和跟进提醒类型已经大量确认。

可以先进入以下实现范围：

- 页面结构、路由、导航和角色权限框架。
- 登录流程和 4 个初始化账号方案。
- 数据上传页、上传记录和基础上传校验。
- 按平台拆分的 CSV / XLSX 解析、字段筛选、订单过滤、销售金额计算和日期标准化流程。
- 客户列表页筛选、排序入口、分页、虚拟滚动和返回状态保留。
- 健康度和跟进提醒的接口结构、输出字段和占位展示。

暂不建议提前固化以下内容：

- 客户唯一标识和客户名单历史治理。
- 活跃 / 沉默 / 未拿货客户最终定义。
- 健康度最终得分算法。
- 跟进提醒最终触发阈值和汇总映射。
- 同比 / 环比最终计算规则。
- 客户详情页依赖客户名单的字段来源。
