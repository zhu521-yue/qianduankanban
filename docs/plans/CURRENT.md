## 当前判断依据

- 后端入口以 `8.4/src/backend/http.py` 和 `8.4/src/backend/routes.py` 为准。
- 共享上传服务 `8.4/src/backend/services/upload_service.py` 只能保留请求模型、外壳校验和平台分发，不允许在共享服务里推断字段、金额、数量、覆盖策略或指标刷新口径。
- 有赞平台处理器以 `8.4/src/backend/services/youzan_upload_processor.py` 和 `8.4/src/backend/core/youzan_upload.py` 为准，当前只实现单文件字段抽取和预览。
- 前端真实后端适配在 `frontend/src/services/backend-service.ts`，上传页在 `frontend/src/pages/SalesUploadPage.vue`，数据合并页在 `frontend/src/pages/DataMergePage.vue`，上传记录页在 `frontend/src/pages/UploadRecordsPage.vue`。

## 已删除的开发项

- 不做待跟进提醒：不开发提醒生成、提醒阈值、重点客户、提醒合并和跟进中心。
- 不做客户列表 / 客户详情补字段项：不补合作开始时间、平均单次拿货金额、客户详情同比 / 环比、活跃程度筛选、复杂排序、单客户产品趋势等。
- 不做正式安全链路：不做正式账号密码登录、会话 Cookie、密码哈希、会话过期、强权限校验、request_id 安全追踪等。
- 删除跨平台通用销售上传实现：不保留统一字段映射、统一行校验、统一销售事实表写入、统一日汇总刷新、统一指标刷新。

## 保留的功能优先级

- P0：平台专属销售上传框架。保留接口外壳和平台处理器占位，后续按平台分别实现解析、校验、入库、聚合和指标刷新。
- P0：上传记录和最新业务日期。当前只保留占位返回；待平台专属入库规则明确后，再决定记录表、数据日期来源和展示口径。
- P1：看板必要数据补齐。只保留当前看板页面需要的客户指标、产品结构或聚合数据；不加入待跟进提醒。
- P1：轻量元数据接口。只用于统一小组、平台、日期边界、上传限制，避免前后端各维护一份常量；不扩展成权限安全系统。
- P1：轻量接口契约。保留清晰错误消息、日期和金额格式即可，不做复杂生产级响应封装。

## 关键决策

- 禁止在共享上传服务里做跨平台字段解析、金额 / 数量计算、去重覆盖、写库和指标刷新。
- 后续每个平台必须拥有自己的处理器；平台处理器内部独立定义文件格式、字段含义、校验规则、计算口径、写入目标表和刷新指标。
- 有赞当前只确认“从一份上传文件中抽取 8 个字段并生成预览表”；这不是正式入库规则，也不是金额、数量、退款和指标口径。
- 有赞预览当前只做字段抽取；未做业务键合并、去重、冲突解决或覆盖。
- 当前上传接口只是端到端占位 / 预览，不能向用户暗示“上传后数据库已更新”或“看板已刷新”。
- `data` 字段清单只做字段盘点，不推导业务口径；CSV 读取前 30 行候选表头，XLSX 读取前 60 行候选表头，纯数值 / 空表不强行当作字段。
- `python-multipart` 可保留，因为 HTTP 层仍需要接收 multipart 文件；`openpyxl` 不作为通用上传依赖保留。
