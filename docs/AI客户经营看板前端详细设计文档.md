> 对应原型：`前端页面效果预览.html`  
> 文档性质：页面、交互、状态、权限与前后端数据契约的详细设计基线  
> 适用对象：产品、UI、前端、后端、测试  
> 版本：V1.0  
> 日期：2026-07-31

---

## 1. 文档目标

本文档按照当前静态原型的各个页面进行拆解，用于指导后续正式前端工程化实现、接口设计和测试验收。

文档中的内容分为三类：

1. **原型已体现**：当前 HTML 中已经可以查看或操作的结构与效果。
2. **正式开发要求**：静态原型没有完整实现，但正式系统必须具备的加载、异常、权限和状态处理。
3. **待业务确认**：页面展示位已经存在，但计算公式、数据来源或业务阈值尚未最终确认。

当前 HTML 只用于视觉和页面结构确认，不代表以下内容已经实现：

- 真实登录态和后端权限校验。
- 真实路由与浏览器历史记录。
- 真实接口请求和数据库数据。
- 文件上传、解析、校验与入库。
- 客户列表真实筛选、排序、分页和虚拟滚动。
- 健康度、同比 / 环比、跟进提醒的最终算法。

## 2. 产品定位与设计目标

### 2.1 产品定位

AI 客户经营看板面向渠道部主管和三个业务小组组长，集中展示销售、客户、趋势、健康度和待跟进信息，并为组长提供最新销售数据与客户名单上传入口。

### 2.2 核心目标

- 主管快速了解渠道整体及各小组经营状态。
- 组长快速了解本组整体及各平台经营状态。
- 从汇总数据进入客户列表，再进入客户详情形成完整分析链路。
- 将客户风险、异常下滑和建议动作以只读方式集中展示。
- 通过平台化上传入口统一接收最新 CSV / XLSX 数据。

### 2.3 第一版设计边界

第一版以“查看和分析”为主，不建设完整 CRM 工作流。

第一版不包含：

- 在线新增、编辑或删除跟进记录。
- 在线修改跟进状态或填写客户反馈。
- 客户列表导出。
- 历史上传文件下载。
- 主管上传数据。
- 密码修改、找回、重置和账号管理。
- 健康度、同比 / 环比和提醒规则的在线配置。

## 3. 用户角色与权限

### 3.1 主管

数据范围：全部小组及全部平台。

可访问内容：

- 渠道总览页。
- 私域组、达人组、分销组的组别分析页。
- 各小组客户列表页。
- 各小组客户详情页。
- 全部小组的上传记录，只读查看。

不可执行操作：

- 上传销售数据。
- 上传客户名单。
- 修改跟进状态或跟进内容。

默认登录落点：渠道总览页。

### 3.2 组长

数据范围：账号绑定的唯一小组及其下属平台。

可访问内容：

- 本组组别分析页。
- 本组客户列表页。
- 本组客户详情页。
- 本组数据上传页。
- 自己产生的上传记录。

不可执行操作：

- 切换或访问其他小组。
- 查看其他小组数据。
- 修改跟进状态或跟进内容。

默认登录落点：本组组别分析页。

### 3.3 权限实现原则

- 前端根据登录会话控制菜单、路由和操作入口。
- 后端必须再次校验角色和数据范围，不能只依赖前端隐藏按钮。
- 主管和组长在各自数据范围内不做字段级权限差异。
- 正式系统不应保留原型中的“主管端 / 组长端”手动角色切换器；该控件只用于效果预览。
- 组长的小组归属来自账号会话，不允许通过前端参数任意修改。

### 3.4 当前原型权限缺口

需求要求主管可以查看全部上传记录，但主管端当前没有上传页或上传记录入口，并且原型会阻止主管进入 `upload` 状态。

正式开发建议拆分职责：

- 组长：数据上传页中同时展示自己的上传记录。
- 主管：增加独立的“上传记录”只读入口，只展示记录表格，不展示文件选择区。

该入口是否加入主管侧边栏，需要产品确认后再实现。

### 4.3 建议路由

```text
/login
/overview
/groups/:groupKey/analysis
/groups/:groupKey/customers
/groups/:groupKey/customers/:customerName
/groups/:groupKey/uploads/:dataType
/upload-records
```

路由说明：

- `groupKey` 取值建议固定为 `private`、`talent`、`distribution`。
- `dataType` 取值建议固定为 `sales`、`customers`。
- 第一版客户详情使用“当前小组 + 客户名称”定位，`customerName` 必须进行 URL 编码。
- 后续取得稳定客户 ID 后，应迁移为 `/customers/:customerId`，避免重名和改名问题。

## 5. 全局页面框架

### 5.1 桌面端结构

页面由固定侧边栏和主内容区组成：

- 侧边栏宽度：278px。
- 主内容区最小宽度：0，允许内部表格横向滚动。
- 主内容区内边距：上 26px、左右 30px、下 42px。
- 侧边栏桌面端吸顶，占满视口高度并允许内部滚动。

主内容区从上到下分为：

1. 页面标题区。
2. 页面工具栏。
3. 页面业务内容区。

### 5.2 侧边栏

组成：

- 品牌区：AI 标识、产品名称、说明文字。
- 角色信息区：原型中用于主管 / 组长预览切换；正式系统改为只读角色信息。
- 小组区：主管可切换小组；组长只展示账号所属小组，不提供切换。
- 页面导航区：根据角色和当前小组动态生成。
- 权限说明区：向原型评审者解释当前角色边界；正式系统可缩减为账号和所属组信息。

导航选中态使用高亮背景和左侧强调线；悬停态只提供轻量背景变化。

### 5.3 页面标题区

字段：

- 角色视图标识，例如 `SUPERVISOR VIEW`。
- 页面主标题。
- 页面说明文字。

正式开发建议：

- 角色英文标识可保留为视觉辅助，但不能代替中文角色信息。
- 客户详情页主标题使用“客户名称 · 客户详情页”。
- 页面说明文字只描述当前页面范围，不展示数据库更新时间。

### 5.4 工具栏

工具栏随页面类型变化：

- 总览 / 分析页：时间周期切换和自定义日期控件。
- 客户列表页：展示列表能力说明，实际筛选控件位于列表上方。
- 客户详情页：返回客户列表和定位方式说明。
- 数据上传页：销售数据 / 客户名单切换，以及数据库最新日期提示。

### 5.5 全局时间规则

- 统一使用北京时间。
- 默认不展示当日数据，以昨日为最大可选日期。
- 数据最早日期为 2025-02-01。
- 近 7 日和近 30 日按自然日计算，包含周末，不包含当天。
- 页面数据暂定每天北京时间 12:00 完成更新。
- 看板页面不显示数据更新时间；销售数据上传页显示数据库更新截止日期。

### 5.6 数字与文案格式

- 金额：`¥` + 千分位，不强制显示小数，例如 `¥2,198,400`。
- 数量：整数 + 千分位。
- 比率：保留 1 位小数并显示 `%`。
- 正增长：前置 `+`，使用绿色。
- 负增长：前置 `-`，使用红色。
- 金额或数量无数据：显示 `0`。
- 无法计算的比率：显示 `暂无`，不能按 `0%` 处理。
- 日期：`yyyy-mm-dd`。
- 日期时间：`yyyy-mm-dd HH:mm`。

## 6. 视觉设计规范

### 6.1 视觉风格

整体采用浅色数据看板风格：

- 页面背景为低饱和蓝灰色，并使用轻量蓝 / 青色光晕增强层次。
- 侧边栏使用深蓝黑色，突出导航和角色边界。
- 内容卡片采用白色或半透明白色。
- 主要强调色为蓝色，青色和紫色用于图表辅助序列。
- 绿色表示健康或正向变化，黄色表示观察，红色表示风险和负向变化。

### 6.2 核心设计变量

| 类型 | 原型值 | 用途 |
| --- | --- | --- |
| 主色 | `#2563eb` | 主要按钮、选中态、链接 |
| 深主色 | `#1d4ed8` | 主要按钮渐变终点 |
| 青色 | `#06b6d4` | 图表与品牌辅助色 |
| 绿色 | `#10b981` | 健康、成功、正向变化 |
| 黄色 | `#f59e0b` | 观察状态 |
| 红色 | `#ef4444` | 风险、失败、负向变化 |
| 紫色 | `#7c3aed` | 图表对比序列 |
| 主文本 | `#172033` | 标题、主要数字 |
| 次文本 | `#6b7280` | 辅助说明、字段名 |
| 分割线 | `#e5e7eb` | 表格、卡片边界 |
| 大圆角 | `22px` | 面板、卡片、上传区 |
| 控件圆角 | `10px–16px` | 输入框、按钮、标签 |

### 6.3 字体层级

- 页面 H1：26–38px，自适应视口。
- 模块标题 H2 / H3：17px。
- KPI 数值：28px。
- 常规正文：13–14px。
- 辅助说明和标签：12px。

### 6.4 状态颜色

| 状态 | 颜色语义 | 展示方式 |
| --- | --- | --- |
| 健康 / 成功 | 绿色 | 浅绿背景胶囊标签 |
| 观察 | 黄色 | 浅黄背景胶囊标签 |
| 风险 / 流失预警 / 失败 | 红色 | 浅红背景胶囊标签 |
| 普通信息 | 蓝色 | 浅蓝背景标签或提示条 |
| 中性说明 | 蓝灰色 | 灰色标签 |

注意：流失预警当前复用风险色。若后续需要区分“风险”和“流失预警”，建议为流失预警使用更深红色或增加图标 / 文案，而不是只依赖颜色。

### 6.5 通用组件

正式工程建议沉淀以下组件：

- `AppShell`：侧边栏与内容框架。
- `RoleScopeNavigation`：角色、小组和页面导航。
- `PageHeader`：标题和说明。
- `PeriodToolbar`：周期和自定义日期。
- `SectionCard`：业务模块容器。
- `StatusChip`：健康度、上传状态、风险标签。
- `MetricGroup`：一组小型指标。
- `DataTable`：固定表头、横向滚动、排序和分页。
- `TrendBars`：同比 / 环比条形指标。
- `SalesComparisonChart`：自定义时间总额对比柱状图。
- `UploadDropzone`：文件选择和上传状态。
- `EmptyState`、`LoadingState`、`ErrorState`：统一页面状态。

页面组件只负责展示，业务口径和平台清洗规则不能写入组件内部。

## 7. 页面一：渠道总览页

### 7.1 页面定位

主管独有页面，回答以下问题：

- 渠道整体销售表现如何？
- 私域组、达人组、分销组分别贡献多少？
- 客户规模和活跃情况如何？
- 当前销售趋势是增长还是下降？
- 有多少健康、观察、风险和流失预警客户？
- 当前有哪些客户需要重点跟进？

### 7.2 页面入口与权限

- 入口：主管登录后的默认页面。
- 主管：可访问。
- 组长：不可访问，导航中不显示，直接访问时后端返回无权限。

### 7.3 页面布局

```text
页面标题
时间工具栏
销售指标模块
趋势指标模块
客户指标模块（整体 + 三个小组）
健康度总览模块 | 待跟进提醒模块
```

### 7.4 时间工具栏

周期选项：

- 昨日。
- 近 7 日。
- 近 30 日。
- 自定义时间。

自定义时间时新增：

- 开始日期。
- 结束日期。
- 对比单位：按月 / 按季度 / 按半年。

校验规则：

- 开始日期不得早于 2025-02-01。
- 结束日期不得晚于昨日。
- 开始日期不得晚于结束日期。
- 校验失败时在对应日期控件附近展示错误，不发送接口请求。

### 7.5 销售指标模块

固定表格列：

- 维度。
- 昨日总金额。
- 近 7 日总销售金额。
- 近 30 日总销售金额。

固定行：

- 整体。
- 私域组。
- 达人组。
- 分销组。

设计原则：

- 固定三周期始终展示，不随当前时间 Tab 隐藏。
- 当前周期 Tab 主要控制趋势、客户、健康度和跟进等周期性内容。
- 自定义时间未选择时，销售模块底部展示说明占位，不展示无意义的图表。

### 7.6 自定义时间销售柱状图

仅在“自定义时间”下展示。

内容：

- 当前自定义日期范围。
- 总销售金额。
- 当前所选小组销售金额。
- 小组切换：私域组 / 达人组 / 分销组。

重要口径：

- 柱状图展示所选时间段的汇总金额。
- 不按每日拆分。
- 日期字段表示整个自定义时间范围。
- 切换小组只改变对比柱，不改变总销售金额。

### 7.7 趋势指标模块

非自定义周期展示：

- 销售同比。
- 日环比。
- 周环比。
- 月环比。

自定义周期展示：

- 同比。
- 环比。

表现形式：指标名称 + 比例条 + 百分比。

状态规则：

- 正值使用绿色。
- 负值使用红色。
- 无法计算时显示“暂无”，不绘制比例条。

待确认内容：

- 同比、日环比、周环比、月环比和自定义环比的最终计算公式。
- 自定义日期跨月、跨季度时允许选择哪些对比单位。
- 无历史同期数据时的展示与排序规则。

### 7.8 客户指标模块

展示维度：

- 整体。
- 私域组。
- 达人组。
- 分销组。

每个维度展示：

- 客户总数。
- 有拿货客户数。
- 未拿货客户数。
- 活跃客户数。
- 沉默客户数。

正式开发建议将当前周期名称放在模块标题或卡片辅助文案中，避免用户无法判断客户指标对应昨日、近 7 日还是近 30 日。

待确认内容：

- 有拿货、未拿货、活跃、沉默的最终定义。
- 客户总数按当前名单快照还是所选时间范围内有效名单计算。

### 7.9 健康度总览模块

展示字段：

- 健康客户数。
- 观察客户数。
- 风险客户数。
- 流失预警客户数。
- 规则状态。

已确定框架：100 分制，等级为健康、观察、风险、流失预警。

当前规则参数尚未全部确认，正式系统在算法未落地前必须显示“规则待确认”，不能用演示分数作为真实结果。

### 7.10 待跟进提醒模块

列表项包含：

- 客户名称。
- 提醒原因或异常数据。
- 建议动作。
- 提醒类型标签，例如重点风险、异常下滑、待跟进。

第一版只读：

- 不提供“处理”“完成”“填写反馈”等按钮。
- 可点击客户名称进入详情，但是否启用该跳转需在正式交互稿中确认。

### 7.11 页面状态

- 加载中：各模块使用骨架屏，保持页面布局稳定。
- 局部失败：单个模块展示重试按钮，不阻塞其他模块。
- 全页无数据：销售和客户数量显示 0，比率显示“暂无”。
- 权限失败：展示无权限页，不回显任何渠道数据。

### 7.12 验收标准

- 组长无法访问该页面。
- 固定销售表准确展示整体和三个小组。
- 自定义时间只能选择有效日期。
- 自定义图表支持小组切换且总额不随小组切换。
- 非自定义和自定义趋势项数量符合设计。
- 所有风险和跟进内容为只读。

## 8. 页面二：组别分析页

### 8.1 页面定位

用于查看某一小组的整体经营情况及其下属平台表现。

三个小组共用同一页面结构和组件，通过 `groupKey`、平台元数据和接口参数驱动，不复制三套页面代码。

### 8.2 页面入口与权限

- 主管：可切换私域组、达人组、分销组。
- 组长：只能查看账号所属小组。
- 组长登录后的默认页面。

### 8.3 页面结构


### 8.4 与渠道总览页的差异

| 项目 | 渠道总览页 | 组别分析页 |

### 8.5 平台维度

- 有赞平台。

- 本组整体。

- 本组整体。

固定表格列与渠道总览一致。

行结构改为：

- 当前组下属各平台。

自定义时间下支持平台切换，图表展示：

- 本组总销售金额。
- 当前所选平台销售金额。

### 8.7 客户、健康度与跟进模块

所有模块必须同时支持：

- 本组整体。
- 当前组各平台。

当前原型的客户指标按多个卡片展示，但健康度和待跟进模块只展示单组示例。正式接口和 UI 需要明确当前模块展示的是本组整体，还是允许切换平台；建议沿用销售模块的平台切换控件，避免一次渲染过多重复卡片。

### 8.8 页面状态与验收

除渠道总览页通用状态外，还需满足：

- 切换小组时自动重置为该组第一个平台。
- 切换小组时清理上一个小组的平台筛选和图表维度。
- 组长请求其他组数据时必须被后端拒绝。

## 9. 页面三：客户列表页

### 9.1 页面定位

展示当前小组范围内的客户经营指标，支持搜索、筛选、排序、分页，并作为客户详情页的唯一标准入口。

客户列表页与组别分析页并列，不继承组别分析页的时间或平台筛选条件。

### 9.2 数据范围

- 主管：当前选中小组的客户。
- 组长：账号所属小组的客户。
- 默认基准日期：昨日。

### 9.3 页面布局

```text
页面标题
列表能力说明工具栏
筛选区
客户数据表格
分页区
```

### 9.4 筛选区

筛选项：

- 平台：全部平台 + 当前小组下属平台。
- 健康度：全部、健康、观察、风险、流失预警。
- 跟进状态：全部、待跟进、处理中、已记录、无需跟进。
- 客户名称：模糊搜索。

交互建议：

- 下拉筛选变化后立即请求第一页数据。
- 客户名称输入采用 300–500ms 防抖。
- 搜索内容去除首尾空格。
- 提供“清空筛选”入口，恢复默认条件。
- 第一版不提供业务负责人筛选。

### 9.5 表格字段

1. 客户名称。
2. 平台。
3. 昨日销售金额。
4. 近 7 日销售金额。
5. 近 30 日销售金额。
6. 拿货次数。
7. 最近拿货时间。
8. 同比。
9. 月环比。
10. 周环比。
11. 日环比。
12. 健康度。
13. 跟进状态。
14. 建议跟进动作。

### 9.6 排序

可排序字段：

- 昨日销售金额。
- 近 7 日销售金额。
- 近 30 日销售金额。
- 同比。
- 月环比。
- 周环比。
- 日环比。

交互规则：

- 第一次点击：降序。
- 第二次点击：升序。
- 第三次点击：恢复默认排序。
- 同时只允许一个主排序字段。
- 当前排序方向必须有明确图标，不使用始终显示的 `↑↓` 代替真实状态。
- “暂无”比率建议排在有效数值之后，最终规则需产品确认。

### 9.7 表格交互

- 客户名称使用链接样式，点击进入客户详情页。
- 表头吸顶。
- 表格最小宽度大于内容区时横向滚动。
- 建议桌面端固定“客户名称”首列，避免横向滚动后丢失行上下文。
- 表格可视区域最大高度约 548px。
- 大数据量必须使用服务端分页；虚拟滚动只优化当前页 DOM 渲染，不能代替分页。
- 第一版不支持导出。

### 9.8 分页

- 每页固定 20 条。
- 展示当前范围和总条数，例如“展示 1–20 条，共 86 条”。
- 支持上一页、下一页和页码切换。
- 请求新页时保留筛选与排序。
- 总页数较多时使用省略号，不渲染全部页码。

### 9.9 返回状态保留

从客户详情页返回时必须恢复：

- 平台筛选。
- 健康度筛选。
- 跟进状态筛选。
- 客户名称搜索词。
- 排序字段和方向。
- 当前页码。
- 表格横向和纵向滚动位置，建议保留。

建议将列表查询状态写入 URL Query，例如：

```text
?platform=youzan&health=watch&followStatus=pending&keyword=杭州&sort=sales30d&order=desc&page=2
```

这样浏览器返回、页面刷新和链接分享都可以稳定恢复状态。

### 9.10 页面状态

- 首次加载：表格骨架屏。
- 筛选加载：保留表头，表体显示加载状态，避免页面高度跳动。
- 无数据：显示“暂无数据”，并保留筛选区。
- 接口失败：表格区域显示错误原因和重试按钮。
- 比率不可计算：显示“暂无”。
- 文本过长：建议动作列允许换行并提供悬停完整内容。

### 9.11 验收标准

- 列表只出现当前小组客户。
- 平台选项随小组变化。
- 搜索、筛选、排序和分页可以组合使用。
- 客户名称可进入正确详情。
- 返回列表时状态完整恢复。
- 表头固定，宽表可横向滚动。
- 页面没有导出入口。

## 10. 页面四：客户详情页

### 10.1 页面定位

围绕单个客户展示基础档案、销售表现、拿货趋势、产品结构、健康度和历史跟进信息。

### 10.2 入口与定位

- 标准入口：客户列表页点击客户名称。
- 第一版定位键：当前小组 + 客户名称。
- 页面顶部提供“返回客户列表”。
- 返回时恢复列表查询状态。

风险说明：客户名称不是稳定主键。后续数据中出现重名或改名时，必须迁移到稳定客户 ID。

### 10.3 页面布局

```text
页面标题
返回工具栏
客户基础信息 | 健康度评价
销售概览 KPI
拿货趋势 | 同比环比
产品明细
跟进记录
```

### 10.4 客户基础信息模块

字段：

- 当前小组。
- 平台。
- 客户名称。
- 合作开始时间。
- 客户状态。
- 健康度等级标签。

待确认：

- 合作开始时间的数据来源。
- 客户状态与健康度是否为两个独立概念。
- 客户名单是否稳定提供上述字段。

### 10.5 健康度评价模块

展示内容：

- 0–100 分健康度评分。
- 健康度等级。
- 风险原因。
- 建议动作。

已确定评分框架：

- 销售金额表现：30 分。
- 拿货频次：25 分。
- 最近一次拿货时间：20 分。
- 产品结构健康度：15 分。
- 同比 / 环比趋势：10 分。

等级区间：

- 健康：80–100。
- 观察：60–79。
- 风险：40–59。
- 流失预警：40 以下。

当前逐项得分、扣分公式和硬条件优先级仍待确认。在算法未确认前，正式页面应展示“规则待确认”，不能展示固定演示分数 78。

### 10.6 销售概览模块

四个 KPI：

- 累计销售金额。
- 近 7 日销售金额。
- 近 30 日销售金额。
- 平均单次拿货金额。

辅助信息：

- 累计金额可展示同比。
- 近 7 日金额可展示周环比。
- 近 30 日金额可展示月环比。
- 平均单次拿货金额展示拿货次数。

待确认：

- 累计销售金额的起算日期。
- “单次拿货”按订单、按支付记录还是按拿货日期聚合。

### 10.7 拿货趋势模块

支持粒度：

- 日。
- 周。
- 月。

展示序列：

- 拿货金额。
- 拿货次数。

正式图表要求：

- 明确 X 轴时间和 Y 轴单位。
- 金额与次数量纲不同，建议使用双轴或切换指标，不建议共用单轴。
- 支持横向滚动或缩放查看长时间序列。
- 悬停显示周期、金额和次数。
- 无数据时显示空状态，不渲染伪造柱形。

### 10.8 同比环比模块

指标维度：

- 销售金额。
- 拿货次数。
- 产品拿货数量。

每个维度展示同比和环比。

当前原型复用了页面全局趋势组件，只能表现一组销售趋势。正式开发需要为三个指标维度建立清晰分组，不能只显示“金额 / 次数 / 数量”标签而缺少对应数值。

### 10.9 产品明细模块

字段：

- 产品名称。
- 产品分类。
- 拿货数量。
- 拿货金额。
- 拿货次数。
- 最近拿货时间。

待确认：

- 当前平台源数据主要提供产品编码，产品名称与产品分类的数据来源尚未闭环。
- 若正式数据没有产品分类，不能用演示分类填充；应隐藏该列或显示“暂无”，但调整前需要产品确认。

建议能力：

- 默认按拿货金额降序。
- 产品名称过长时允许换行。
- 数据较多时分页，不在详情页一次加载全部产品。

### 10.10 跟进记录模块

字段：

- 业务跟进状态。
- 跟进时间。
- 客户反馈。
- 下一步动作。

第一版只读：

- 不显示新增、编辑、删除和状态切换控件。
- 数据为空时显示“暂无跟进记录”或“规则待确认”。
- 外部跟进数据的来源和同步方式仍待确认。

### 10.11 页面状态与验收

- 客户不存在：展示“客户不存在或已失效”，提供返回列表入口。
- 无权限：不返回客户信息。
- 局部接口失败：对应模块单独重试。
- 所有展示模块均保留，不能因组件复用而合并或删除。
- 返回按钮恢复列表完整状态。
- 跟进模块无编辑入口。

## 11. 页面五：数据上传页

### 11.1 页面定位

组长按本组平台上传最新销售数据或客户名单，并查看自己的上传记录。

### 11.2 权限

- 组长：可访问、可上传本组平台文件。
- 主管：不展示上传入口，不允许上传。
- 组长不能通过修改平台参数上传其他组平台文件。

### 11.3 页面结构

```text
页面标题
数据类型切换 + 数据库更新日期
上传操作卡
├── 平台切换
├── 文件选择区
└── 上传规则提示
平台字段模板卡
上传记录卡
```

### 11.4 数据类型切换

两个子页面：

- 销售数据上传页。
- 客户名单上传页。

切换时：

- 保留当前小组。
- 默认选择当前组第一个平台。
- 清空尚未提交的文件和校验错误。
- 重新加载对应数据类型的字段模板。

### 11.5 平台切换

只显示当前组平台：

- 私域组：有赞平台、快团团平台。
- 达人组：抖音平台、快手小店、微店。
- 分销组：聚水潭线上平台、阿里巴巴平台。

一个文件只能对应一个平台，平台上下文必须随上传请求提交并由后端校验。

### 11.6 文件选择区

支持格式：

- `.csv`。
- `.xlsx`。

建议交互：

1. 点击选择文件或拖拽文件。
2. 展示文件名、大小、平台和数据类型。
3. 前端执行扩展名和文件大小基础校验。
4. 用户确认上传。
5. 显示上传与处理进度。
6. 返回成功结果或结构化错误。

当前原型只有“选择文件”按钮，正式开发必须增加选择后确认、进度、成功和失败状态，避免选中文件后立即产生不可预期写入。

### 11.7 重复上传规则

当前需求：当日反复上传时，通过上传文件名计算哈希；哈希相同则覆盖当日上传数据。

设计风险：仅对文件名计算哈希无法识别“同名但内容不同”与“改名但内容相同”。正式实现前应确认以下二选一：

- 按文件内容计算哈希，作为文件唯一指纹。
- 按“上传日期 + 平台 + 数据类型 + 原始文件名”生成幂等键。

覆盖动作应在结果中明确返回：

- 新增导入。
- 覆盖导入。
- 重复文件，无需处理。

### 11.8 上传校验

通用校验：

- 文件格式是否支持。
- 文件是否为空。
- 必需字段是否存在。
- 日期是否可解析。
- 金额和数量是否为有效数值。
- 状态字段是否可以用于平台过滤规则。
- 平台和账号所属组是否匹配。

失败结果至少包含：

- 错误行号。
- 错误字段。
- 错误原因。
- 原始值，可按敏感性决定是否返回。

建议支持下载错误清单，但当前需求明确不允许下载历史上传文件；错误清单是否允许下载需要单独确认。

### 11.9 上传状态机

```text
未选择文件
→ 已选择
→ 前端校验中
→ 待确认上传
→ 上传中
→ 服务端解析中
→ 成功 / 失败 / 部分失败
```

状态规则：

- 上传中禁止重复点击。
- 用户切换页面前，如上传尚未提交，可直接清空；如已上传，应提示任务仍在处理中。
- 服务端解析耗时较长时建议返回任务 ID，由前端轮询状态。
- 部分失败是否允许有效行入库需要业务确认；默认建议整批失败，避免数据缺口难以识别。

### 11.10 数据库更新日期

销售数据上传页展示：

```text
数据库已更新到：yyyy-mm-dd
```

该日期必须来自接口，不应写死。

客户名单上传页是否展示客户名单版本日期尚未确认；若没有该概念，可以不展示。

### 11.11 页面状态与验收

- 平台范围严格匹配当前组。
- 文件类型校验正确。
- 上传前明确展示文件、平台和数据类型。
- 上传期间不可重复提交。
- 错误结果包含行号和字段。
- 成功后刷新上传记录和数据库更新日期。
- 主管看不到上传控件，接口也拒绝主管上传。

```text
platform + customers → 客户名单字段模板
```

在客户名单字段确认前，客户名单上传页只能作为页面壳或显示“模板待确认”，不能按销售字段执行客户名单校验。

## 13. 页面六：上传记录

### 13.1 展示位置

- 组长：数据上传页右侧 / 下方，展示本人记录。
- 主管：建议独立只读页面，展示全部小组记录。

### 13.2 字段

- 上传人。
- 上传时间。
- 平台。
- 文件名。
- 状态：成功 / 失败。
- 数据类型：销售数据 / 客户名单。

“数据类型”在原型中已经展示，但既有需求记录中仍有过“是否增加”的待确认项。由于销售数据和客户名单共用记录列表，建议正式保留该字段。

### 13.3 权限与生命周期

- 组长只能看到本人记录。
- 主管可以看到全部组记录。
- 不提供历史文件下载。
- 失败记录保留。
- 超过 6 个月的日志过期。

### 13.4 建议筛选

主管记录较多时建议支持：

- 小组。
- 上传人。
- 平台。
- 数据类型。
- 状态。
- 上传日期范围。

组长页面可以只保留状态和日期范围，避免筛选过度复杂。

### 13.5 状态展示

- 成功：绿色标签。
- 失败：红色标签。
- 处理中：正式系统建议增加蓝色标签。
- 部分失败：若业务允许部分成功，使用黄色标签并展示成功 / 失败行数。

### 13.6 空状态与验收

- 无记录：显示“暂无上传记录”。
- 记录表不提供文件下载按钮。
- 上传成功或失败后立即出现新记录。
- 组长不能通过筛选或参数看到他人记录。

## 14. 前端状态与数据流设计

### 14.1 状态分层

建议将状态分为四层：

```text
会话状态
├── 当前用户
├── 角色
└── 所属小组

路由状态
├── 当前页面
├── 当前查看小组
└── 当前客户

查询状态
├── 时间周期
├── 日期范围
├── 平台 / 健康度 / 跟进状态
├── 搜索词
├── 排序
└── 分页

临时交互状态
├── 当前上传类型
├── 当前上传平台
├── 已选文件
└── 上传进度与错误
```

### 14.2 状态归属原则

- 登录用户、角色和所属组：全局会话状态。
- 页面、小组、客户：路由参数。
- 可恢复的筛选、排序、分页：URL Query。
- 上传文件、进度和临时错误：页面局部状态。
- 接口数据缓存：按“角色数据范围 + 页面 + 查询参数”作为缓存键。

### 14.3 状态转换

```text
登录成功
├── 主管 → 渠道总览
└── 组长 → 本组组别分析

主管切换小组
→ 更新 groupKey
→ 清空旧平台选择
→ 请求新小组数据

客户列表点击客户
→ 保留列表 Query
→ 进入客户详情
→ 返回时恢复 Query 和滚动位置

上传类型或平台切换
→ 清空已选文件
→ 清空校验结果
→ 加载对应字段模板
```

### 14.4 避免复杂度扩散

- 页面组件不判断平台原始字段差异。
- 页面组件不实现健康度和同比 / 环比计算。
- 权限判断集中在路由守卫和后端授权层，不分散到每个卡片。
- 小组 / 平台关系由统一元数据提供，不在多个页面重复维护数组。
- `overview` 和 `analysis` 可以共享展示组件，但必须通过明确的 `scope` 数据结构驱动，不能在组件内部散布大量角色条件判断。

建议统一作用域结构：

```ts
type DashboardScope =
  | { level: 'channel' }
  | { level: 'group'; groupKey: 'private' | 'talent' | 'distribution' };
```

## 15. 建议前端数据结构

以下为正式工程的数据契约建议，不代表当前 HTML 已实现。

```ts
type Role = 'supervisor' | 'leader';
type GroupKey = 'private' | 'talent' | 'distribution';
type Period = 'yesterday' | '7d' | '30d' | 'custom';
type CompareUnit = 'month' | 'quarter' | 'half';
type HealthLevel = 'healthy' | 'watch' | 'risk' | 'churn_warning';
type UploadDataType = 'sales' | 'customers';
type UploadStatus = 'processing' | 'success' | 'failed' | 'partial';

type QueryRange = {
  period: Period;
  startDate?: string;
  endDate?: string;
  compareUnit?: CompareUnit;
};

type DimensionMetric = {
  key: string;
  label: string;
  yesterdayAmount: number;
  last7DaysAmount: number;
  last30DaysAmount: number;
};

type CustomerListQuery = {
  groupKey: GroupKey;
  platform?: string;
  healthLevel?: HealthLevel;
  followStatus?: string;
  keyword?: string;
  sortBy?: string;
  sortOrder?: 'asc' | 'desc';
  page: number;
  pageSize: 20;
};

type UploadValidationError = {
  row: number;
  field: string;
  reason: string;
  rawValue?: string;
};
```

设计要求：

- 后端金额建议返回整数分或十进制定点字符串，避免前端浮点误差。
- 比率允许返回 `null`，前端统一显示“暂无”。
- 枚举值与中文展示文案分离，避免用中文作为程序状态。
- 日期统一返回 ISO 格式字符串。

## 16. 建议接口边界

### 16.1 会话与元数据

```text
POST /api/auth/login
GET  /api/session
GET  /api/meta/groups
GET  /api/meta/platforms?groupKey=private
GET  /api/meta/upload-templates?platform=youzan&dataType=sales
```

### 16.2 看板

```text
GET /api/dashboard/overview
GET /api/dashboard/groups/:groupKey
```

查询参数包含周期、日期范围和对比单位。

建议一次返回页面主体数据，避免五个模块各自发起大量重复请求；对于计算耗时或独立失败概率较高的模块，可以拆为并行接口。

### 16.3 客户

```text
GET /api/groups/:groupKey/customers
GET /api/groups/:groupKey/customers/:customerName
```

客户列表接口负责服务端筛选、排序和分页。

客户详情可以按模块拆分或一次返回；第一版数据量不大时建议一次返回，降低状态拼装复杂度。

### 16.4 上传

```text
POST /api/groups/:groupKey/uploads
GET  /api/groups/:groupKey/uploads/:taskId
GET  /api/upload-records
GET  /api/data-freshness?groupKey=private&platform=youzan
```

上传请求必须包含：

- 平台。
- 数据类型。
- 文件。
- 幂等键或文件哈希。

接口错误必须返回稳定错误码和结构化字段错误，不能只返回一段不可解析文本。

## 17. 加载、空、异常与权限状态

### 17.1 加载状态

- 首屏使用与最终布局一致的骨架屏。
- 切换筛选时保留旧数据并显示局部加载提示，或使用骨架替换；同一页面保持一致。
- 上传解析使用明确进度或“处理中”状态。

### 17.2 空状态

- 销售金额、客户数量：显示 0。
- 无法计算的同比 / 环比：显示“暂无”。
- 客户列表：显示“暂无数据”。
- 上传记录：显示“暂无上传记录”。
- 跟进记录：显示“暂无跟进记录”。
- 规则未确认：显示“规则待确认”。

### 17.3 异常状态

- 网络错误：提示“加载失败，请重试”。
- 参数错误：定位到具体控件。
- 无权限：独立 403 页面，不展示业务数据。
- 资源不存在：404 状态，并提供返回上级页面入口。
- 上传字段错误：结构化展示行号、字段、原因。

### 17.4 防重复与竞态

- 快速切换小组、周期或筛选时取消旧请求，防止旧响应覆盖新页面。
- 上传按钮在处理中禁用。
- 同一查询只保留最新响应。
- 页面卸载时清理轮询和定时器。

## 18. 响应式设计

### 18.1 大屏：大于 1180px

- 侧边栏固定在左侧。
- KPI 四列。
- 双栏模块保持左右布局。
- 客户筛选四列。

### 18.2 中屏：721–1180px

- 侧边栏改为页面顶部普通区块。
- KPI、指标、筛选和基础信息改为两列。
- 双栏模块、客户详情首屏和上传布局改为单列。
- 页面标题区改为纵向。

正式工程建议将顶部侧边栏进一步改为可折叠菜单；直接完整展开角色、小组和导航会占用过多垂直空间。

### 18.3 小屏：不大于 720px

- 主内容区左右内边距缩小到 14px。
- 工具栏纵向排列。
- KPI、指标、筛选和基础信息全部单列。
- 宽表保持横向滚动，不强行压缩所有列。
- 按钮可换行但点击区域高度不少于 40px。

### 18.4 移动端边界

该系统属于桌面数据看板，移动端以“可查看”为目标，不要求在窄屏上完成复杂宽表分析和大文件上传。若未来要求移动端高频使用，需要重新设计客户列表卡片视图和导航，而不是仅依赖 CSS 堆叠。

## 19. 可访问性与易用性

- 所有按钮必须有可读文本或 `aria-label`。
- 选中态不能只依赖颜色，需同时使用文字、图标或形态变化。
- 表格排序按钮应支持键盘操作并声明 `aria-sort`。
- 输入框必须有可关联的标签，不能只依赖 placeholder。
- 焦点态必须清晰可见。
- 健康度和上传状态需要文字标签，不能只显示颜色。
- 图表需要文本摘要，保证无法读取图形时仍能理解关键数据。
- 弹窗和上传错误出现后，应将焦点移动到错误摘要。
- 正文和背景对比度应达到 WCAG AA 基本要求。

---

## 20. 性能设计

- 客户列表采用服务端分页，每页 20 条。
- 当前页宽表可使用虚拟滚动，但不要一次请求全部客户。
- 图表库按页面懒加载。
- 小组和平台元数据全局缓存。
- 看板接口按查询条件缓存，切换回已访问周期时优先复用缓存并后台刷新。
- 搜索输入防抖。
- 快速切换筛选时取消旧请求。
- 文件上传使用流式传输或分片策略需根据实际文件大小决定，不能把大文件完整读入浏览器内存后再处理。

---

## 21. 安全设计

- 所有业务接口必须验证会话。
- 组长的数据范围必须由后端根据账号绑定组确定。
- 文件扩展名、MIME 类型和真实文件结构都要校验。
- 上传文件名必须转义，不能直接作为服务器路径。
- 限制文件大小、行数、列数和解析时间。
- CSV 内容需要防范公式注入；若未来允许导出错误清单，需要对 `=`, `+`, `-`, `@` 开头内容进行处理。
- 页面输出客户名称、文件名和反馈文本时必须进行 HTML 转义。
- 上传错误信息不能泄露服务器路径、SQL、堆栈和内部配置。

## 22. 测试与验收范围

### 22.1 权限测试

- 主管可访问渠道总览和全部组数据。
- 主管不能上传。
- 组长只能访问绑定小组。
- 组长不能读取其他组客户和上传记录。
- 手动修改 URL 或请求参数不能绕过后端权限。

### 22.2 时间测试

- 最大日期始终为北京时间昨日。
- 最小日期为 2025-02-01。
- 开始日期晚于结束日期时禁止提交。
- 近 7 日 / 近 30 日包含周末且不包含当天。
- 无同期数据时显示“暂无”。

### 22.3 页面测试

- 渠道总览维度为整体 + 三个小组。
- 组别分析维度为本组整体 + 组内平台。
- 切换小组后平台选项同步刷新。
- 客户列表筛选、排序、分页可组合。
- 详情返回后列表状态恢复。
- 宽表在中小屏可以横向滚动。
- 跟进模块始终只读。

### 22.4 上传测试

- CSV / XLSX 正常上传。
- 非支持格式被拦截。
- 缺字段、日期错误、金额错误返回准确行号和字段。
- 重复点击不会产生重复任务。
- 同名文件覆盖规则符合最终幂等设计。
- 上传完成后记录刷新。
- 历史文件不可下载。

### 22.5 状态测试

- 加载、空数据、接口失败、无权限、资源不存在均有明确页面反馈。
- 旧请求不会覆盖新筛选结果。
- 上传任务轮询在页面离开后正确停止。

## 23. 待确认事项清单

以下事项不应由前端自行假设：

1. 有拿货、未拿货、活跃、沉默客户的最终定义。
2. 同比、日环比、周环比、月环比和自定义环比的最终公式。
3. 健康度各维度具体得分 / 扣分公式和硬条件优先级。
4. 跟进提醒触发阈值、合并规则和重点客户定义。
5. 客户稳定唯一标识以及重名、改名处理方式。
6. 客户名单真实字段模板。
7. 合作开始时间、客户状态、产品名称和产品分类的数据来源。
8. 累计销售金额起算日期和平均单次拿货金额口径。
9. 主管查看上传记录的正式页面入口。
10. 上传记录是否最终保留“数据类型”列；本设计建议保留。
11. 重复上传应使用内容哈希还是业务幂等键。
12. 上传部分失败时整批回滚还是有效行入库。
13. 错误清单是否允许下载。
14. 健康度和跟进模块在组别分析页中如何切换平台维度。
15. 微店模板字段使用 `SKU编码` 还是实际源字段 `SKU编码(自定义)`。

## 24. 正式工程模块建议

建议按职责拆分，而不是按照页面复制代码：

```text
src/
├── app/                    # 路由、会话、权限守卫、全局错误边界
├── domain/
│   ├── organization/       # 小组与平台元数据
│   ├── dashboard/          # 看板查询结构和展示模型
│   ├── customer/           # 客户列表、详情、健康度展示模型
│   └── upload/             # 上传状态机、模板、记录
├── pages/
│   ├── overview/
│   ├── group-analysis/
│   ├── customer-list/
│   ├── customer-detail/
│   └── upload/
├── components/
│   ├── layout/
│   ├── metrics/
│   ├── charts/
│   ├── tables/
│   └── feedback/
└── services/               # API 调用、DTO 转换、错误映射
```

职责原则：

- `pages` 负责组合模块和读取路由状态。
- `domain` 负责业务展示模型、查询参数和状态转换。
- `components` 保持无业务或弱业务，接收明确数据。
- `services` 负责接口 DTO 转换，防止后端字段直接扩散到全部组件。
- 平台原始数据清洗属于后端数据处理层，禁止进入前端工程。

## 25. 结论

当前原型已经明确了主要页面结构、角色视角、视觉方向和关键交互入口，可以作为正式前端的视觉基线。

正式开发时需要优先完成三个收敛：

1. 将原型中的单一全局 `state` 拆成会话、路由、查询和上传局部状态。
2. 将渠道总览与组别分析抽象为统一的作用域驱动组件，同时保持产品要求的模块结构不变。
3. 在接入真实数据前关闭第 23 节中的关键业务口径，尤其是客户状态、同比 / 环比、健康度、客户名单字段和上传幂等规则。

未确认规则必须以“暂无”或“规则待确认”呈现，不得使用原型演示值代替真实业务结论。
