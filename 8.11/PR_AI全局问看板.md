# PR：AI 全局问看板——受控自然语言问数、证据表格与图表

> 状态：已实施并完成自动验证，待用户页面审查
> 功能批次：AI 智能看板第 3 个功能
> 前置功能：AI 经营洞察、AI 客户经营诊断已实施
> 数据库：沿用 PostgreSQL `weidian`，只读九个店铺白名单派生表
> 产品定位：面向公司内部业务部门的自然语言经营分析，不提供客户回复或自动业务操作

## 1. 功能目标

在所有已登录页面提供全局“问看板”入口。业务人员不需要逐个切换模块，可以直接用自然语言询问权限范围内的经营问题，例如：

- “本月哪个店铺销售额下降最多？”
- “达人组最近6个月销售趋势怎么样？”
- “本季度退款最高的是哪个店铺？”
- “列出半年销售额最高的20个风险客户。”
- “当前半年金额Top5商品是什么？”
- “哪些店铺的数据日期比较旧？”

系统将问题转换为受控指标查询，调用后端固定只读工具，并返回：

1. 简短经营结论。
2. 可复核的关键数字。
3. 表格或趋势/对比图。
4. 查询范围、统计周期和数据库来源。
5. 数据新鲜度、空值或口径警告。
6. 可定位到原看板模块的“在看板中查看”入口。

## 2. 这个功能与 AI 的直接关系

本功能不是把固定规则摘要包装成 AI。配置模型后，AI 参与完整的自然语言分析链路：

### 2.1 第一次模型调用：理解问题

模型把业务人员的自然语言问题解析成受控 JSON 查询计划：

```json
{
  "metric_key": "sales_change_rate",
  "scope_key": "all",
  "grain": "month",
  "as_of": "2026-08-11",
  "group_by": "store",
  "comparison": "previous_period",
  "filters": {},
  "limit": 9,
  "output_type": "bar"
}
```

模型不能输出 SQL、Schema、表名或用户角色。查询计划必须经过 Pydantic、指标目录和登录权限三层校验。

### 2.2 后端确定性执行

后端根据 `metric_key` 调用固定只读工具，从数据库查询真实结果，并验证合计、变化率、日期和权限。模型不接触数据库连接，也不能自由选择表。

### 2.3 第二次模型调用：解释证据

模型基于验证后的结构化证据生成经营结论和原因解释。数字卡、表格和图表直接使用工具结果，不从模型文本中提取数字。

因此 AI 真正负责“理解业务问题”和“解释查询结果”，确定性代码负责“权限、查询、数字和验证”。

## 3. 首版支持范围

### 3.1 支持的问题

| 问题类型 | 示例 | 返回形式 |
| --- | --- | --- |
| 单一指标 | 本月销售额是多少？ | 数字卡 + 当前/上一周期 |
| 周期对比 | 本月比上月增长还是下降？ | 数字卡 + 对比说明 |
| 范围贡献 | 哪个店铺本月销售额最高？ | 排名表 + 柱状图 |
| 销售趋势 | 最近6个月销售趋势怎么样？ | 折线图 + 周期表 |
| 退款分析 | 本季度哪个店铺退款最高？ | 排名表 + 柱状图 |
| 客户数量 | 半年有多少活跃购买客户？ | 数字卡 + 范围说明 |
| 客户排名 | 半年销售最高的风险客户有哪些？ | 客户表格 |
| 健康分布 | 当前风险和流失预警客户有多少？ | 状态表 + 柱状图 |
| 商品排行 | 当前半年金额Top5商品是什么？ | 商品表 + 柱状图 |
| 微店预售 | 微店半年预售金额和主要商品？ | 数字卡 + 商品表 |
| 数据新鲜度 | 哪些店铺数据日期较旧？ | 店铺日期表 + 警告 |
| 驱动解释 | 本月销售下降主要来自哪些店铺？ | 贡献表 + AI解释 |

### 3.2 暂不支持

- 任意 SQL 或任意表字段查询。
- 未进入指标目录的自由计算。
- 利润、毛利、库存、成本、转化率等数据库未统一提供的指标。
- 销售预测、退款预测或客户流失概率预测。
- 跨店铺合并相同客户ID或昵称。
- 客户级退款归因。
- 自动修改看板、客户状态、规则或数据库记录。
- 自动上传文件或确认写入数据库。
- 生成面向客户的回复、话术或营销文案。
- 多智能体协作。

- 用户问题中出现的任意表名或字段名。
- 指标目录未登记的表或字段。
- 当前登录账号权限之外的 Schema。
- AI 配置、账号密码、数据库连接信息和其他系统配置。

## 5. 时间口径与数据新鲜度

1. 当前看板已有 `day/week/month/quarter/half` 五种粒度，问看板继续使用 `periods.py` 的同一周期规则。
2. 当前页面有明确 `as_of` 时默认继承页面日期。
3. 页面没有日期时，后端使用当前权限范围的最新销售日期。
4. 用户明确指定日期时，以指定日期为准，但不得晚于数据库可用日期后仍声称数据完整。
5. 多店铺结果返回每个店铺的 `latest_data_date`。
6. 某店铺数据早于查询截止日期时，该行增加 `stale=true`，回答中显示数据滞后警告。
7. 为保持与原看板一致，首版不悄悄把查询日期改成其他日期；日期差异必须显式展示。
8. 当前值或上一周期为零时不计算虚假百分比，返回 `change=null` 并说明缺少可靠比较基数。

## 6. 权限模型

后端只能从加密会话取得真实角色：

- 主管：可查询 `all`、三个业务组、平台和九个店铺范围。
- 达人组账号：只允许达人组及其平台、店铺。
- 私域组账号：只允许私域组及其平台、店铺。
- 分销组账号：只允许分销组及其店铺。

执行流程：

1. 页面上下文提供默认 `scope_key`，不提供角色。
2. AI 解析得到的 `scope_key` 必须存在于 `SCOPE_STORES`。
3. 使用 `resolve_scope(current_user.role, scope_key)` 做最终权限校验。
4. 即使模型或前端提交了越权范围，也返回 `SCOPE_FORBIDDEN`，不执行工具。
5. 客户排名结果中的每一行都携带 `store_key`，后端再次确认店铺属于解析后的范围。

## 7. 后端接口

### 7.1 请求

`POST /api/v1/ai/query`

```json
{
  "question": "本月哪个店铺销售额下降最多？",
  "context": {
    "scope_key": "all",
    "as_of": "2026-08-11",
    "grain": "month",
    "route": "#/manager/overall"
  },
  "history": [
    {"role": "user", "content": "最近半年哪个组销售最高？"},
    {"role": "assistant", "content": "达人组半年销售额最高。"}
  ]
}
```

约束：

- `question`：1至1000字符。
- `history`：最多6条，只用于理解“那私域组呢”等追问；不能作为数字证据。
- `scope_key`：只能作为默认上下文，最终必须重新校验。
- `grain`：只接受当前五种粒度。

### 7.2 查询计划

模型或本地解析器生成的计划必须通过 `AiQueryPlan`：

```text
metric_key
scope_key
grain
as_of
group_by: total | group | platform | store | period | customer | product | health_status
comparison: none | previous_period
filters: 仅登记字段
limit: 1—100
output_type: cards | table | line | bar
```

每个指标在目录中单独声明允许的粒度、分组、筛选、最大行数和默认输出形式。通用 Pydantic 校验通过后，还必须通过指标自身约束。

### 7.3 响应

    "query_plan": {
      "metric_key": "sales_change_rate",
      "scope_key": "all",
      "grain": "month",

## 8. 受控执行流程

```text
自然语言问题
  → AI意图解析 / 本地模板解析
  → AiQueryPlan校验
  → resolve_scope权限校验
  → 指标目录选择固定工具
  → Repository只读查询
  → EvidenceValidator验证
  → 确定性表格、图表、证据
  → AI解释 / 规则摘要降级
  → 前端问看板抽屉
```

### 8.1 意图解析

- 已配置 AI：模型按照 JSON Schema 输出查询计划。
- 模型输出不是合法 JSON、指标越界或参数不合法时，不执行数据库查询。
- 后端不得执行模型生成的 SQL、表名、列名或路由。
- 对“最好、重点、表现差”等词，返回实际采用的定义，例如“按销售额环比从低到高排序”。

### 8.2 固定只读工具

新增 `AiToolRegistry`，工具内部复用 `DashboardRepository`、`CustomerRepository`、`catalog.py` 和 `periods.py`，不复制另一套 AI 专用业务口径。

需要补充的 Repository 能力：

- 按店铺返回销售当前值、上一周期值和变化率。
- 按小组、平台或店铺聚合贡献。
- 返回限定周期数的销售趋势。
- 按店铺返回退款当前值、上一周期值和变化率。
- 返回受限条数的客户排名与健康状态。
- 按店铺返回数据新鲜度。

所有 Schema 使用 `psycopg.sql.Identifier`，其他值使用参数绑定。

### 8.3 证据验证

`EvidenceValidator` 至少完成：

1. 合计值与明细行合计一致。
2. 变化率由当前值和上一周期值重新计算。
3. 表格和图表引用同一结果集。
4. 返回周期与查询计划一致。
5. 返回店铺全部属于已授权范围。
6. 客户、商品和趋势结果不超过目录上限。
7. 数据新鲜度晚于或等于表格实际来源日期，否则增加警告。
8. 空结果不交给模型推测原因。

验证失败时返回 `AI_QUERY_VALIDATION_FAILED`，不展示未经验证的 AI 回答。

## 9. 未配置 AI 与失败降级

用户的 API Key 仍然在登录后由当前角色的设置页配置。

### 9.1 未配置 API Key

问看板仍可处理一组确定性模板问题：

- 当前销售额及上一周期对比。
- 最近若干周期销售趋势。
- 店铺销售或退款排名。
- 客户销售排名和指定健康状态筛选。
- Top商品、健康分布、微店预售和数据新鲜度。

页面显示 `规则问数`，并提示配置 AI 后可理解更灵活的自然语言和追问。

### 9.2 模型失败

- 意图解析失败：尝试本地模板解析；匹配成功则 `degraded=true` 后继续。
- 本地模板也无法识别：返回 `AI_QUERY_UNSUPPORTED` 和可改问示例，不执行查询。
- 结果解释模型失败：使用工具结果生成确定性摘要，表格和图表继续展示。

### 9.3 AI 配置可用

页面显示 `AI 问数`。一次完整复杂问题最多调用模型两次：一次解析意图，一次解释已验证证据。后端限制历史条数、结果行数和摘要长度，避免无界调用。

## 10. 前端交互

### 10.1 全局入口

- 已登录后的所有页面显示固定“问看板”按钮。
- 点击后从右侧打开 `AskDashboardDrawer`。
- 抽屉不遮挡退出登录和关键确认操作。
- 上传页、设置页没有明确日期时，显示“将使用当前权限范围最新数据”。

### 10.2 页面上下文

新增由 `Home` 管理的当前看板上下文：

```text
route
scope_key
as_of
trend_grain
refund_grain
customer store_key/customer_id（进入客户详情时）
```

`DashboardPage` 在数据或筛选变化后上报上下文；抽屉顶部清楚展示本次查询范围、截止日期和粒度。用户可以修改范围，但选项只能来自 `/meta/options` 返回的权限范围。

### 10.3 抽屉结构

- 标题：“AI 问看板”。
- 模式：`AI 问数` / `规则问数` / `已降级`。
- 当前范围和日期。
- 推荐问题，按照当前角色和页面动态展示。
- 对话区，保留当前浏览器会话内最近问题。
- 结论区。
- 证据卡片。
- 表格区，默认20行。
- 折线图或柱状图。
- 数据来源、口径和警告。
- “在看板中查看”按钮。

不提供客户回复、话术、自动操作、导入或数据库写入按钮。

### 10.4 结果展示原则

- 结论先行，表格和图表随后。
- 图表只在确实有比较或趋势时展示。
- 表格列定义由后端返回，前端只按受控类型格式化。
- 金额、百分比和数量使用统一格式。
- 不能比较时显示“暂无可靠对比”，不显示 `0%`。
- 来源至少包含指标、周期和店铺 Schema/派生表。
- 数据滞后、空值和受限范围必须可见。

## 11. 错误处理

| 场景 | 错误码或行为 |
| --- | --- |
| 未登录 | `AUTH_REQUIRED`，沿用统一登录处理 |
| 范围越权 | `SCOPE_FORBIDDEN` |
| 指标不支持 | `AI_QUERY_UNSUPPORTED`，返回支持示例 |
| 日期或粒度非法 | `DATE_INVALID` / `GRAIN_INVALID` |
| 结果为空 | 正常响应，`empty=true`，不生成原因 |
| 数据验证失败 | `AI_QUERY_VALIDATION_FAILED` |
| 模型解析失败且无本地匹配 | `AI_QUERY_UNSUPPORTED` |
| 模型解释失败 | 规则摘要降级，表格和图表保留 |
| 数据库异常 | 沿用统一后端错误，不返回SQL或凭据 |

## 14. 测试计划

### 14.1 指标目录与工具

- 每个指标只允许登记粒度、分组和筛选。
- 未登记指标、表名和字段被拒绝。
- Schema 只来自 `catalog.py`。
- 销售、退款、客户、健康、商品、预售和新鲜度结果可与现有 Repository 对账。
- 当前值、上一周期值和变化率计算正确。
- 客户最大100行、商品最大20行、趋势最大24点。

### 14.2 权限与安全

- 未登录返回 `AUTH_REQUIRED`。
- 三个业务组不能查询其他组。
- 主管可以查询全部授权范围。
- 前端伪造角色无效。
- 问题包含 SQL、Schema 或表名时不执行自由 SQL。
- 问题要求写入、删除、上传、修改状态或回复客户时拒答。
- 响应不包含 API Key、连接字符串和SQL正文。

### 14.3 AI 与降级

- 已配置时合法 JSON 计划能够执行。
- 模型非法 JSON 不直接执行工具。
- 未配置时常用模板问题可以查询。
- 模型意图解析失败时本地模板可降级。
- 模型解释失败时保留规则摘要、表格和图表。
- 模型不能改变证据、数字、图表或目标路由。

### 14.4 数据验证

- 总计与明细合计一致。
- 变化率可由当前值和上一值复算。
- 表格和图表使用同一结果集。
- 日期和粒度与计划一致。
- 数据滞后显示警告。
- 空结果不生成虚构原因。

### 14.5 前端

- 所有登录角色都有问看板入口。
- 抽屉继承并展示当前范围、日期和粒度。
- 支持推荐问题和自由提问。
- 结论、证据、表格、图表、来源和警告分区展示。
- 关闭抽屉或发起新问题时取消旧请求。
- 旧响应不能覆盖新问题。
- “在看板中查看”只使用后端受控目标。
- 不出现客户回复、自动操作或任意SQL入口。

### 14.6 回归

- AI经营洞察和客户助手不受影响。
- 登录、退出、权限、上传和设置功能不受影响。
- 后端完整测试通过。
- 前端构建、渲染测试和新增组件 lint 通过。
