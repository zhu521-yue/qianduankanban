# AI 客户看板：前端模块与数据库表映射

> 文档状态：当前实现（可直接编辑）  
> 数据库：PostgreSQL `weidian`  
> 后端接口前缀：`/api/v1`  
> 原则：前端只展示和格式化；数据范围、周期、聚合、权限与数据库查询均由后端负责。

## 1. 总体调用链

```text
前端页面 app/page.tsx
  ├─ 登录/会话 ────────────────> /auth/* ───────> backend/config/accounts.json
  ├─ 看板全部经营模块 ─────────> /dashboard ───> 各店铺销售/商品/退款/健康度/预售表
  ├─ 客户列表 ─────────────────> /customers ───> 客户销售表 + 昵称映射表 + 健康度表
  ├─ 客户详情 ─────────────────> /customers/{store}/{customer} ─> 客户销售/客户商品/健康度表
  ├─ 客户分析助手 ─────────────> /ai/chat ──────> 客户详情真实数据 + 后端 AI 环境配置
  ├─ 上传预览 ─────────────────> /uploads/sales ─> 只在后端内存校验，不写数据库
  └─ 设置展示 ─────────────────> /settings/* ───> 健康度表 + 后端 .env
```

后端主要映射位置：

- 店铺、schema、权限范围：`backend/app/catalog.py`
- 表名、日期字段、金额字段：`backend/app/repositories.py`
- 模块聚合口径：`backend/app/services.py`
- HTTP 参数与返回：`backend/app/main.py`
- 前端 API 类型和请求：`frontend/app/api.ts`
- 前端模块展示：`frontend/app/page.tsx`

## 4. 看板页面：每个模块的表、字段与口径

所有经营模块由 `GET /api/v1/dashboard` 一次返回。参数：`scope_key`、可选 `as_of`、`trend_grain`、`refund_grain`。不传 `as_of` 时，后端先查询当前范围各 `{schema}.daily_sales.MAX(transaction_date)`，取最大值作为页面默认统计日期。

### 4.1 顶部“数据更新至”和统计日期

| 展示内容 | 数据表/字段 | 口径 |
|---|---|---|
| 默认统计日期 | 每个 `{schema}.daily_sales.transaction_date` | `MAX(transaction_date)`；跨店铺取各店最大日期中的最大值 |
| 数据更新至 | 同上 | 返回 `latest_data_date` |
| 用户选择日期 | 前端日期控件传 `as_of` | 后端按该日期确定所属日/自然周/月/季度/半年周期 |

### 4.2 KPI：半年销售额

- 表：`{schema}.half_year_sales`
- 周期字段：`period_start`、`period_end`
- 金额字段：`half_year_transaction_amount`
- 当前值：当前业务半年内匹配周期行的金额合计；跨店铺相加。
- 环比：`(当前半年金额 - 上一半年金额) / 上一半年金额`；上一期为 0 时返回 `null`。

### 4.3 KPI：本月销售额

- 表：`{schema}.monthly_sales`
- 周期字段：`period_start`、`period_end`
- 金额字段：`monthly_transaction_amount`
- 当前值与环比：当前月合计，并与上一月同口径比较。

### 4.4 KPI：半年客户数

- 表：`{schema}.customer_half_year_sales`
- 字段：`period_start`、`period_end`、`customer_id`、`half_year_transaction_amount`
- 口径：当前半年 `half_year_transaction_amount > 0` 的 `COUNT(DISTINCT customer_id)`；跨店铺直接相加，因为不同店铺的同名客户仍是不同经营实体。

### 4.5 KPI：半年高频商品数

- 表：`{schema}.half_year_product_sales`
- 字段：`period_start`、`period_end`、`product_code`、`half_year_product_quantity`
- 口径：当前半年数量大于 0 的去重 `product_code`。跨店铺时后端按商品编码集合去重。

### 4.6 销售走势

| 前端粒度 | 表 | 日期字段 | 金额字段 |
|---|---|---|---|
| 日 | `{schema}.daily_sales` | `transaction_date` | `transaction_amount` |
| 周 | `{schema}.weekly_sales` | `period_start`, `period_end` | `weekly_transaction_amount` |
| 月 | `{schema}.monthly_sales` | `period_start`, `period_end` | `monthly_transaction_amount` |
| 季度 | `{schema}.quarterly_sales` | `period_start`, `period_end` | `quarterly_transaction_amount` |
| 半年 | `{schema}.half_year_sales` | `period_start`, `period_end` | `half_year_transaction_amount` |

口径：后端生成截至 `as_of` 的最近 6 个同粒度周期，逐周期按页面 scope 内店铺求和。前端柱高只按返回金额归一化，不生成或修正业务数字；标题金额取序列最后一期，变化率用最后两期计算展示。

### 4.7 自然周客户健康度

- 客户范围表：每个 `{schema}.customer_weekly_sales`
- 客户范围：严格匹配统计日期所在自然周的 `period_start`、`period_end`，按 `customer_id` 去重；客户总数即该自然周客户范围数量。
- 健康度表：每个 `{schema}.customer_health_detail`
- 关联键：`customer_id`
- 健康记录日期筛选：`period_start <= as_of`
- 取数规则：只为上述自然周客户范围关联健康记录，每个客户按 `period_end DESC, updated_at DESC` 取截至统计日期的最新一条；没有健康记录的客户归入“未评分”。
- 状态字段：`customer_health_status`
- 分数字段：达人组 4 个 schema 用 `customer_health_score`；其余 schema 用 `customer_score`。
- 状态说明：`state_instructions`
- 建议动作：`follow_up_action`
- 分布：在自然周客户范围内按 `customer_health_status` 分组计数，因此各状态数量之和与客户总数一致。
- 健康客户：状态为“高活跃”“活跃”“稳定”的客户数之和。
- 健康客户占比：健康客户数 / 健康度客户总数。

### 4.8 半年高频商品 Top5

- 表：`{schema}.half_year_product_sales`
- 统计周期：根据统计日期确定其所在的业务半年，并以该半年的 `period_start`、`period_end` 查询。
- 字段：`product_code`、`half_year_product_quantity`、`half_year_transaction_amount`、`period_start`、`period_end`
- 数量 Top5：按当前半年 `SUM(half_year_product_quantity)` 降序。
- 金额 Top5：按当前半年 `SUM(half_year_transaction_amount)` 降序。
- 跨店铺：先按 `product_code` 合并各 schema 的数量与金额，再排序。
- 双榜商品：数量 Top5 和金额 Top5 的 `product_code` 交集数量。

### 4.9 退款金额分析

| 前端粒度 | 表 | 金额字段 |
|---|---|---|
| 周 | `{schema}.weekly_refunds` | `weekly_refund_amount` |
| 月 | `{schema}.monthly_refunds` | `monthly_refund_amount` |
| 季度 | `{schema}.quarterly_refunds` | `quarterly_refund_amount` |
| 半年 | `{schema}.half_year_refunds` | `half_year_refund_amount` |

所有表均以 `period_start`、`period_end` 定位周期。展示当前期、上一期、环比及最近 6 期趋势；跨店铺逐 schema 相加。没有从销售额反推退款，也没有前端模拟退款率。

### 4.10 微店商品预售

只有 `weidian` schema 具备下列表，且后端仅统计 `is_presale = true`：

| 粒度 | 表 | 数量字段 | 金额字段 |
|---|---|---|---|
| 月 | `weidian.monthly_product_presales` | `monthly_presale_quantity` | `monthly_presale_transaction_amount` |
| 季度 | `weidian.quarterly_product_presales` | `quarterly_presale_quantity` | `quarterly_presale_transaction_amount` |
| 半年（当前页面展示） | `weidian.half_year_product_presales` | `half_year_presale_quantity` | `half_year_presale_transaction_amount` |

页面展示当前半年预售金额、数量、商品种数和金额 Top5。页面范围不含微店或金额为 0 时不展示该模块。

## 5. 客户列表模块

接口：`GET /api/v1/customers`。当前前端传 `grain=half`，搜索词和分页均传后端，不再对前端数组筛选。

### 5.1 时间粒度与客户销售表

| 粒度 | 表 | 金额字段 | 拿货次数字段 |
|---|---|---|---|
| 日 | `{schema}.customer_daily_sales` | `transaction_amount` | 无独立字段，按当日记录计数 |
| 周 | `{schema}.customer_weekly_sales` | `weekly_transaction_amount` | `weekly_purchase_count` |
| 月 | `{schema}.customer_monthly_sales` | `monthly_transaction_amount` | `monthly_purchase_count` |
| 季度 | `{schema}.customer_quarterly_sales` | `quarterly_transaction_amount` | `quarterly_purchase_count` |
| 半年 | `{schema}.customer_half_year_sales` | `half_year_transaction_amount` | `half_year_purchase_count` |

### 5.2 每一列来源

| 前端列 | 表/字段 | 说明 |
|---|---|---|
| 排名 | 后端分页后的位置 | 查询先按 `period_amount DESC` 排序，前端只加分页偏移 |
| 客户 ID | 客户销售表 `customer_id` | 精确业务 ID |
| 客户昵称 | `{schema}.customer_id_mapping` | 字段差异见第 2 节；无昵称字段时回退 `customer_id` |
| 店铺 | `backend/app/catalog.py` 店铺元数据 | 根据 `store_key` 返回中文名，不是业务数值 |
| 半年销售额 | `customer_half_year_sales.half_year_transaction_amount` | 当前半年金额 |
| 拿货次数 | `customer_half_year_sales.half_year_purchase_count` | 当前半年次数 |
| 健康度 | 最新 `customer_health_detail` 的分数字段 | 字段差异见第 2 节；空值显示 0 |
| 状态 | 最新 `customer_health_detail.customer_health_status` | 空值显示“未评分” |

搜索：在后端对 `customer_id` 和映射后的 `display_name` 做不区分大小写包含匹配。分页返回 `total`、`total_pages`、上一页/下一页标记。

## 6. 客户详情页全部模块

接口：`GET /api/v1/customers/{store_key}/{customer_id}`。若不传 `as_of`，取该店铺 `daily_sales` 的最新日期。

### 6.1 客户头部卡

- 客户 ID 与昵称：`{schema}.customer_id_mapping`，找不到映射时再查 `{schema}.customer_daily_sales` 确认客户并以 ID 展示。
- 店铺名：后端店铺目录。
- 健康度、状态、状态说明、跟进动作：该客户在 `{schema}.customer_health_detail` 中截至 `as_of` 的最新一条。

### 6.2 详情 KPI

| 卡片 | 数据来源 |
|---|---|
| 半年销售额 | `customer_half_year_sales.half_year_transaction_amount` 当前周期合计 |
| 半年拿货次数 | `customer_half_year_sales.half_year_purchase_count` 当前周期合计 |
| 本月销售额 | `customer_monthly_sales.monthly_transaction_amount` 当前周期合计 |
| 半年主要商品 | `customer_half_year_product_sales` 返回的金额 Top5 数量；当前 UI 明确标为主要商品，不冒充全部商品数 |

### 6.3 “客户销售与拿货信息”五个维度

| 维度 | 销售/次数表 | 商品表 | 商品金额字段 | 商品数量字段 |
|---|---|---|---|---|
| 日 | `{schema}.customer_daily_sales` | `{schema}.customer_daily_product_sales` | `transaction_amount` | `product_quantity` |
| 周 | `{schema}.customer_weekly_sales` | 不读取客户商品表 | — | — |
| 月 | `{schema}.customer_monthly_sales` | `{schema}.customer_monthly_product_sales` | `monthly_transaction_amount` | `monthly_product_quantity` |
| 季度 | `{schema}.customer_quarterly_sales` | `{schema}.customer_quarterly_product_sales` | `quarterly_transaction_amount` | `quarterly_product_quantity` |
| 半年 | `{schema}.customer_half_year_sales` | `{schema}.customer_half_year_product_sales` | `half_year_transaction_amount` | `half_year_product_quantity` |

商品明细按当前客户、当前周期筛选，按交易金额合计降序返回 Top5。周维度数据库没有 `customer_weekly_product_sales`，因此 UI 明确显示不读取商品表。

### 6.4 客户分析助手

接口：`POST /api/v1/ai/chat`。

- 客户上下文仍从上述客户详情表现场查询，不接受前端伪造的金额、健康度和次数。
- 传给分析上下文的字段：客户 ID/昵称、店铺、健康分、状态、半年销售额、半年拿货次数、风险说明。
- AI 服务地址、模型和密钥来自后端 `.env` 的 `AI_BASE_URL`、`AI_MODEL_NAME`、`AI_API_KEY`。
- 未配置外部 AI 时，后端返回基于真实数据库字段的结构化摘要，不返回前端模拟话术。

## 7. 登录与账号模块

| 模块 | 来源 | 说明 |
|---|---|---|
| 账号资料 | `backend/config/accounts.json` | 独立保管，已被 `.gitignore` 忽略；不使用 `weidian` 业务表 |

## 8. 上传模块

接口：`POST /api/v1/uploads/sales`，固定 `mode=preview`。

- 店铺入口不是前端写死：前端先请求 `/meta/options`，根据当前角色的 `stores` 返回值生成。
- 后端读取 CSV/XLSX，支持标准列及中文别名，校验日期、客户、商品、数量、销售金额、退款金额、预售标记和拿货次数。
- 返回总行数、有效行数、无效行数和前 100 条错误。
- 当前任务只保存在后端进程内存；不读取或写入 `weidian` 中的业务表。
- `mode=commit` 明确返回 `UPLOAD_MAPPING_REQUIRED`。待确认各平台原始列映射、订单唯一键、覆盖/增量和汇总刷新规则后，才能为各 schema 单独实现写库。

## 9. 设置模块

### 9.1 客户状态规则

- 读取接口：`GET /api/v1/settings/health-rules`
- 保存接口：`PUT /api/v1/settings/health-rules`
- 固定顺序：`高活跃 → 活跃 → 稳定 → 观察 → 风险 → 流失预警 → 流失`；前端不能增删、改名或排序。
- 达人组配置表：`public.talent_customer_status_action`；保存后同步组级 `daren.customer_health_detail`、平台级 `doudian.half_year_customer_health`，以及店铺级 `weidian`、`doudianChildren`、`doudianKocotree`、`kuaishouxiaodian` 下的 `customer_health_detail`。
- 私域组配置表：`public.private_customer_status_action`；保存后同步组级 `siyu.customer_health_detail`、平台级 `youzan.customer_health_detail`，以及店铺级 `qijian`、`muyinqijian`、`kuaituantuan` 下的 `customer_health_detail`。
- 分销组配置表：`public.distribution_customer_status_action`；保存后同步 `fenxiao`、`alibaba`、`jushuitan` 下的 `customer_health_detail`。
- 配置表字段：`id`、`customer_health_status`、`state_instructions`、`follow_up_action`、`created_time`、`updated_time`。
- 健康度表同步字段：按 `customer_health_status` 匹配，更新 `state_instructions`、`follow_up_action`、`updated_at`，不修改分数、状态和周期数据。
- 权限：达人/私域/分销账号只能读取和保存本组；后端不接收前端传入的表名或组名。主管端不请求、不展示该模块；直接读取返回空组，直接保存返回 403。
- 事务：配置表 upsert 与本组组级、平台级、店铺级健康度表同步属于同一事务，任一步失败全部回滚。
- 性能：后端先比较 public 现值。无变化时跳过全部健康度表；只修改一个状态时仅更新该状态。分销组的非“流失”状态通过 `fenxiao_customer_health_non_loss_status_idx`、`alibaba_customer_health_non_loss_status_idx` 定位。

### 9.2 AI 接口设置

- 接口：`GET /api/v1/settings/ai`
- 来源：后端 `.env`，不是数据库表。
- 前端收到：`base_url`、`model_name`、`configured` 和密钥掩码。
- 前端不会收到 `AI_API_KEY` 明文，页面只读；修改应直接维护后端 `.env` 后重启服务。

## 10. 周期字段统一规则

| 粒度 | 当前实现定位方式 |
|---|---|
| 日 | `transaction_date = as_of` |
| 自然周 | 周一至周日，匹配 `period_start`、`period_end` |
| 月 | 自然月首日至末日 |
| 季度 | 自然季度首日至末日 |
| 业务半年 | 2月1日—7月31日，或8月1日—次年1月31日 |

后端以 `backend/app/periods.py` 统一生成周期，所有模块复用，不在前端分别计算业务周期。

## 12. 核对结论
